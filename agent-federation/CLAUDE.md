## 2. 근거 추적 체인

모든 주장은 원문까지 따라갈 수 있어야 한다.

```
위키 문서 frontmatter.source_ids
   ↓
10_wiki/00_출처_레코드/SRC-2026-NNNNN.md
   ↓  00_raw_sources/00_registry/inventory-20260716-135050.csv
INV-NNNNNNNN
   ↓
05_processing_cache/text/INV-NNNNNNNN.txt   (본문)
05_processing_cache/tables/INV-NNNNNNNN.tsv (표)
```

출처 레코드 250건 중 233건이 원문까지 도달한다.
미도달 17건(신규 등록·원본 교체·`.zip`/`.msg` 미지원 형식)은 원문 대사가 불가하므로,
해당 SRC를 인용할 때는 **"원문 미도달"을 반드시 병기**한다.

## 4. 절대 규칙

1. **`10_wiki/`·`91_index/`에 쓰지 않는다.** 승인 위키로의 승격은 사람의 판단이다.
   AI가 만든 모든 문서는 `92_outputs/01_drafts/`에 `status: review`로 둔다.
2. **추정하지 않는다.** 근거가 없으면 "없음"이라고 보고한다.
   빈칸을 그럴듯한 문장으로 메우는 것이 이 시스템의 최대 실패 양식이다.
3. **미확인 전제를 숨기지 않는다.** 전제가 있으면 본문에 드러내고 `status: review`를 유지한다.
4. **대외 문서에 원가 구조를 넣지 않는다.**
   `10_wiki/04_회의_의사결정/`의 2026-08-26 결정에 따라, 대외 제출본에서
   **원가율 · 판관비 별도항목 · 제작사 개별 견적**은 금칙이다.
   제작사 견적은 제3자 영업비밀이다(`09_운영_감사` 기록).
5. **외부로 내보내지 않는다 — 단 하나의 통로를 제외하고.**
   이 폴더에서 `git init`·`git push`·`gh`·`curl`·`wget` 업로드를 실행하지 않는다.
   과거 자료 반출 사고의 직접 원인이며, 기록은 `10_wiki/09_운영_감사/`에 있다.
   보관 위치는 회사 OneDrive와 회사 PC로 한정한다.

   **유일한 예외**는 검증자 C가 쓰는 `.claude/scripts/external-verify.mjs`다.
   이 경로만 초안 원문을 외부 API로 보낼 수 있고, 전송 내용 전량이
   `92_outputs/05_orchestration/egress/`에 자동 기록된다.
   **egress 로그를 삭제하거나 수정하지 않는다** — 무엇이 사외로 나갔는지의 유일한 기록이며,
   쓰기 권한 자체가 차단되어 있다.
6. **원본을 수정하지 않는다.** `00_raw_sources/`·`05_processing_cache/`는 읽기 전용이다.

## 5. 파이프라인

기획보고서 요청이 들어오면 `planning-report` 스킬을 따른다.

```
① wiki-librarian (내부 근거) ┐
                             ├→ ③ insight-analyst → ④ report-writer ─┐
② web-scout      (외부 사실) ┘                                        │
                                                                      ▼
                          ┌───────────── 교차 검증 라운드 ─────────────┐
                          │  A auditor-evidence  (근거·수치·금칙)      │
                          │  B auditor-logic     (논증·전제·모순)      │
                          │  C auditor-external  (이종 모델 시각)      │
                          │            ↕ 집필자 반박 · 상호 이의        │
                          │         합의까지 반복 (최대 4라운드)        │
                          └────────────────────────────────────────────┘
                                              ▼
                                          ⑥ 산출
```

- ③이 **핵심**이다. 수집과 집필 사이에 분석을 끼우지 않으면 결과는 사실 나열이 된다.
- ③에서 인사이트 0건이면 진행을 멈추고 사용자에게 보고한다. 억지로 만들지 않는다.
- 검증자 셋의 가치는 **인원수가 아니라 관점 분리**다. 같은 프롬프트로 셋을 돌리면 셋이 같은 소리를 한다.
- **집필자는 지적에 반박할 수 있다.** 단 원문 증거를 제시해야 하며, 증거 없는 반박은 조정자가 자동 기각한다.
- 검증자가 틀렸으면 철회한다. **다수결이 아니다** — 증거가 있으면 셋 다 틀릴 수 있다.
- 전부 `CLOSED`면 자동 산출한다. `ESCALATED`가 하나라도 남으면 중단하고 사람에게 올린다.
- 판정과 무관하게 **합의 로그를 항상** `92_outputs/05_orchestration/`에 남긴다.

## 6. 탐색 요령

- `91_index/index.md`는 103KB(461행)다. **전체를 읽지 말고 Grep으로 진입한다.**
  섹션 헤더는 `## 00. 출처 레코드` ~ `## 10. 산업동향` 형식이다.
- 주제어로 index를 Grep → 후보 문서 ID 확보 → 해당 문서만 Read → `source_ids` 추적.
- 「뒤집는 조건」을 가진 결정 노트는 `grep -l "뒤집는 조건" 10_wiki/04_회의_의사결정/`로 찾는다.
