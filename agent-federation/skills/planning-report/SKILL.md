# 기획보고서 생성 파이프라인

사용자가 기획보고서를 요청하면 아래 순서를 따른다. **단계를 건너뛰지 않는다.**
특히 ③ 분석을 생략하면 결과물이 사실 나열이 되며, 그것이 이 파이프라인이 존재하는 이유다.

---

## 0단계 — 요청 확정

착수 전에 다음 세 가지를 확정한다. 사용자가 말하지 않았고 문맥으로도 알 수 없으면 묻는다.

| 항목 | 기본값 |
|---|---|
| **주제와 질문** | (필수. 무엇을 판단하기 위한 보고서인가) |
| **배포 등급** | `internal`. 사외 제출 가능성이 있으면 `external` |
| **산출 형식** | `.docx`. 임원 보고용이면 `.pptx` 병행 |

배포 등급은 나중에 바꾸기 어렵다. 애매하면 `external`로 잡는다(금칙 검사가 엄격해진다).

---

## ①② 자료수집 — 병렬 실행

`wiki-librarian`과 `web-scout`를 **하나의 메시지에서 동시에** 호출한다.
서로 의존하지 않으므로 순차 실행할 이유가 없다.

- `wiki-librarian` → 내부 근거 카드 + 공백 보고
- `web-scout` → 외부 사실 카드 + 위키 기보유 목록 + 미확보 목록

두 결과가 모두 도착하면 다음으로 넘어간다.

**중단 조건** — 사서의 공백 보고가 질의 항목의 대부분을 차지하면, 여기서 멈추고
사용자에게 "위키에 해당 주제의 근거가 부족하다"고 보고한다. 없는 자료로 보고서를 만들지 않는다.

---

## ③ 인사이트 생성 — 핵심 단계

`insight-analyst`에게 ①②의 카드를 **전부** 넘긴다. 요약해서 넘기지 않는다.
교차는 세부 수치에서 일어나므로 압축하면 인사이트가 사라진다.

### Gate A

| 결과 | 조치 |
|---|---|
| 인사이트 1건 이상 | ④로 진행 |
| **0건** | **파이프라인 중단.** 사용자에게 분석가의 0건 보고서를 그대로 전달하고, 추가 근거 수집 여부를 묻는다 |

**0건일 때 억지로 진행하지 않는다.** 인사이트 없이 쓴 보고서는 이 시스템의 실패다.
분석가가 "추가로 필요한 근거"를 지정했다면 그것만 ①②에 재요청하고 ③을 다시 돌린다.
재시도는 **최대 1회**로 제한한다.

---

## ④ 집필

`report-writer`에게 인사이트 카드 + 근거 카드 + 배포 등급을 넘긴다.
초안은 `92_outputs/01_drafts/YYYY-MM-DD <제목>.md`에 저장된다.

---

## ⑤ 검증

`evidence-auditor`에게 초안 경로와 근거 카드를 넘긴다.

### Gate B

| 판정 | 조치 |
|---|---|
| `PASS` | ⑥으로 진행 |
| `FIX` | ④로 반송. 지적사항만 수정 요청 |
| `BLOCK` | ④로 반송. **반송 2회 후에도 BLOCK이면 파이프라인을 중단하고 사용자에게 보고** |

반송 시 집필자에게 **판정표 전체**를 넘긴다. 요약하면 같은 문제가 반복된다.

무한 루프를 만들지 않는다. 2회 반송으로 해결되지 않는 문제는 근거 자체의 문제이므로
사람의 판단이 필요하다.

---

## ⑥ 산출

검증을 통과한 초안을 기존 사내 스킬로 변환한다. **새 양식을 만들지 않는다.**

| 형식 | 스킬 | 용도 |
|---|---|---|
| `.docx` | `kolon-report` | 기본. 검토·기획보고 |
| `.pptx` | `kolon-ppt` | 임원 보고, 발표용 |

산출물은 `92_outputs/04_reports/`에 저장한다.

---

## 완료 보고

사용자에게 다음을 한 번에 전달한다.

```
- 산출물: 92_outputs/04_reports/<파일명>
- 초안:   92_outputs/01_drafts/<파일명>.md   (status: review)
- 배포등급: internal | external
- 인사이트: n건 (교차유형별 분포)
- 근거: SRC n건 (원문도달 n / 미도달 n)
- 검증: PASS (반송 n회)
- 미확인 전제: n건 — 확인 필요 항목 요약
- 위키 승격 후보: (10_wiki로 올릴 만한 인사이트가 있으면 여기에. 승격은 사용자가 판단)
```

**미확인 전제를 완료 보고에서 빼지 않는다.** 사용자가 그것을 보고 다음 행동을 정한다.

---

## 정기 실행 (선택)

주 1회 다음을 돌리면 위키가 스스로 갱신 신호를 낸다. 비용 대비 산출이 가장 확실한 사용법이다.

1. `web-scout` — 최신 산업동향 Vol.N 이후 기간의 신규 사실 수집
2. `insight-analyst` — **C4(결정 교차)만** 실행.
   `10_wiki/04_회의_의사결정/`의 「뒤집는 조건」이 충족됐는지 기계적으로 재판정
3. 충족·근접 건이 있으면 사용자에게 알림. 없으면 조용히 종료

---

## 원칙

1. **③을 건너뛰지 않는다.** 급하다고 수집 → 집필로 직행하지 않는다.
2. **인사이트 0건은 정당한 결과다.** 만들어내지 않는다.
3. **`10_wiki/`에 쓰지 않는다.** 승격은 사용자의 판단이다.
4. **미확인 전제를 드러낸다.** 숨긴 전제가 사고를 만든다.
5. **외부로 내보내지 않는다.** 이 폴더에서 `git push`·`gh`를 실행하지 않는다.
